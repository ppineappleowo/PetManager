# 百宠集项目总方案

更新：2026-10-07。本文是唯一的产品、结构、部署和后续建议方案；后续直接更新本文，不再新增阶段方案副本。

当前结论：R0–R5 已确定的功能已落地，工程部分已补充发布检查、恢复演练、共享连接池、请求观测、历史读取解耦和前端交互优化。用户本次确认继续保留现有规则，**账号恢复、屏蔽、申诉和点赞聚合另行确定**。这些待定项不算本轮已实现功能。下面同时说明实际能力与验证边界，不把长期建议写成完成项。

## 1. 已确定的产品方向

- 名称：**百宠集**；标语：**每一种宠爱，都有同好。**
- 养宠交流社区为主入口，覆盖所有宠物类型；AI 咨询是辅助功能。
- 首页默认展示全站公开帖子，按最新发布排序；可切换分类、关注流、搜索与话题。推荐算法后置。
- 游客浏览公开内容；发布、互动、个人管理和 AI 需要登录，登录后返回原目标。
- Vue 3 前端，手机双列卡片，电脑自适应多列；个人中心沿用绿色、卡片和侧栏设计。
- 手机号与密码注册，手机号或用户名登录；不恢复短信验证，**登录不使用 Redis 限流**。手机号字段不代表已验证归属。
- PostgreSQL 保存业务事实，Redis 保存短期数据，Chroma 保存检索索引，OSS 保存图片，各自独立。
- 保留 Docker `postgres:latest`、`redis:latest`，备份记录实际镜像 ID；没有本轮拉取或替换运行中的数据库镜像。
- 视频、持久草稿、私信群聊、推荐算法、微服务和多 worker AI 不在本轮。

## 3. 产品规则与数据边界

### 3.1 账号与个人中心

支持密码哈希、JWT、角色、禁用、令牌撤销、密码修改、资料修改、头像和公开主页。个人中心保留未保存离开提醒；确认退出前先处理未保存修改，取消离开不会提前清空登录状态。头像/资料更新不会自行解除管理员隐藏状态。

公开身份使用白名单，不返回手机号、密码、角色或令牌。手机号形式的旧用户名无昵称时显示“宠友_ID”；公开搜索不通过手机号或此类旧用户名定位账号。公开简介和昵称由用户主动填写。

保留已有可见性：禁用账号的历史公开帖不自动下架，其主页、头像、宠物页及关注动态不可用。不能把后端重构当作改变这一规则的理由。

### 3.2 帖子、评论与宠物

- 帖子标题选填，最多 50 字；正文必填，最多 5000 字；0–9 张图片，首图封面。正文纯文本展示。
- 分类为猫、狗、鸟、鱼、小宠、爬宠、其他、多宠/综合；最多 5 个标签，每个 12 字，清理空白与重复。
- 发布即展示，事后治理；编辑不置顶。创建 UUID 防重复，编辑检查版本；作者逻辑删除，下架后编辑不能恢复，作者删除后管理员不能恢复。
- 评论最多 1000 字，按时间顺序分页，默认 20 条；平铺显示回复对象。隐藏或删除保留占位，既有回复不连带删除，不可再回复隐藏评论。
- 每用户每帖唯一点赞，支持幂等与取消；没有评论点赞。下架/删除帖的公开评论和互动不可用。
- 每账号最多 50 只宠物；名字 32 字、品种 50 字、介绍 500 字，生日不能晚于当天。
- 每帖可关联 0–5 只自己的宠物；删除宠物保留帖子并移除关联，递增相关帖子版本。
- 隐藏宠物不出现在公开主页、搜索和帖子关联展示中；主人仍能私下编辑，编辑不解除隐藏。管理页提示原因查询入口，隐藏档案不再链接到不可用公开页。
- AI 辅助日常持久化 `ai_generated` 标识，卡片和详情提示核实；编辑不能抹去已有标识。用户仍需自行检查并点击发布。

### 3.3 收藏、关系与通知

收藏完全私有，不公开收藏者或收藏数量，不发通知。按收藏 ID 倒序，重复收藏不改变顺序，取消后重新收藏生成新 ID。隐藏帖保留关系，恢复后重新可见；删除帖不再展示。接口 `/community/me/bookmarks` 与 `/community/posts/{id}/bookmark` 要求登录。

关注是单向关系，禁止关注自己，操作幂等；数量公开，完整名单仅本人可查，按用户 ID 倒序。禁用账号从计数、名单和关注流排除，关系保留，允许取消但不能新增关注。取消后重新关注是新事件。

通知覆盖评论、回复、关注，不通知自己，同一回复接收者去重。事件与通知使用同一 PostgreSQL 事务；不补发升级前历史事件。隐藏/删除目标和禁用操作者只显示不可用占位，不泄露原文与跳转地址。

通知 API 位于 `/community/me/notifications`，支持列表、摘要、单条已读及 `through_id` 范围内全部已读；后来的通知不会误标。前台可见时每 30 秒轮询，失败退避至最多 5 分钟；隐藏页面、后台和退出时暂停。列表与摘要 `no-store`，不依赖 Redis，不采用消息队列或 WebSocket。

### 3.4 搜索与话题

帖子搜索 `/community/posts?q=&tag=&sort=` 支持标题、正文、标签；关键词之间 AND、字段之间 OR，中文连续子串，英文忽略大小写。`%`、`_`、`!` 按字面转义，全部参数化。按帖子 ID 最新/最早排序，游标分页；并发编辑和治理会改变结果，不是固定快照。

`post_tags` 在帖子创建/编辑事务内维护；话题 `/community/topics` 按公开帖数排序，默认 20、最大 50，同数按标签名。没有独立话题管理或话题关注。

新增 `/community/search/users` 与 `/community/search/pets`，游客可查公开昵称/可公开用户名、宠物名字/品种，按 ID 倒序分页。停用用户、隐藏资料用户及隐藏/删除宠物被过滤；不提供手机检索。

当前没有中文分词、纠错、同义词、相关度排序或个性推荐。已有 9 组帖子中文检索基线和 PostgreSQL 查询计划记录，位于 `tests/test_discovery.py`、`resources/reports/discovery-query-plan.json`。1500 篇模拟帖子测得的数据库耗时仅是小样本，不能承诺生产吞吐量。

## 4. R4 治理运营

### 4.1 举报与作者反馈

举报原因最多 500 字，同一用户同一目标只留一条，包括已处理举报。管理员填写可对举报人展示的说明，可驳回或处理下架；举报结论、目标状态与审计同事务，写入失败整体回滚，不自动封禁账号。

我的举报 `/community/me/reports` 仅本人可读，支持状态筛选、分页及重试。返回本人原因、时间、处理结论/说明；不返回证据快照、隐藏正文、举报人编号或管理员身份。结论反映处理当时结果，只有相关内容当前公开时才提供帖子链接。举报图片仍读取当前附件，没有永久图片证据库。

新增处理记录 `/community/me/moderation?kind=users|community`，作者主动查看资料、头像、宠物、帖子、评论或权限的处理原因和结果。返回安全状态字段，不返回管理员身份和完整前后快照；没有新增推送或申诉入口。

### 4.2 资料、头像和宠物治理

管理员可隐藏/恢复公开资料、头像、宠物档案；原因必填，最多 300 字，检查资料或宠物版本，冲突返回 409。公开资料隐藏时昵称变为默认身份，简介清空；头像单独隐藏。原始记录保留供主人修改和管理员审查。

管理员审查隐藏图片使用带认证的专用接口，公共接口不能绕过隐藏状态。所有治理 API 要求管理员权限；普通用户不能调用。

`user_audit` 和 `community_audit` 记录所属用户、操作者、目标、原因、前后状态及时间，与治理修改同事务。账号权限修改同样记录安全快照，不保存密码、手机号、令牌。新审计自本版本开始，不能为旧记录虚构过去的前后状态。

后台增加“资料治理 / 宠物治理 / 操作审计 / 社区指标”。指标包括公开帖子、发帖人数、公开评论、获他人回复帖子、回复覆盖率、待处理举报、隐藏宠物；为当前状态汇总，没有历史趋势、活跃用户归因或运营精选置顶。

## 5. R5 AI 与知识库

### 5.1 宠物背景、参考资料和反馈

咨询时用户可主动选择自己的宠物，接口校验归属，保存本轮资料快照后传入模型；不自动扫描所有宠物或私人资料。重试使用同一请求及背景约束，失败/停止与完成状态持久化。

检索工具实际返回的本地片段记录来源、版本、片段编号与摘录；网络工具记录 HTTP(S) 链接、标题和摘录。SSE、历史与完成回放保留参考资料；无检索来源时不生成假引用。它们是检索参考，不表示回答每句话已完成事实校验。

本人可对已完成回答标记有帮助/没帮助或取消，接口按账号隔离；管理员看到完成、失败、取消、运行及帮助度汇总。没有凭此自动修改知识或训练模型。

“整理成日常”先提示用户确认，再打开可编辑草稿并标识 AI 辅助；不会自动发布，不直接搬运私人附件。正文只在当前会话内存中一次性传递，路由历史仅保存临时编号；退出、换号或刷新后不恢复草稿。社区帖子尚未自动进入知识索引，授权与撤回机制需在实际建设该能力时另定。

### 5.2 历史与初始化

历史读取和删除独立于模型初始化，读取不会将正在生成的轮次改为失败；用户和管理员历史接口都采用此通道，旧图文历史继续兼容。

社区正常启动不加载 AI。AI 初始化失败不会阻止账号和社区；知识库管理也可独立于完整 Agent 初始化。活跃流式任务仍在单进程内，数据库操作移入线程池；Redis 已接入不等于支持跨 worker 停止或租约。

### 5.3 持久化知识任务与版本

后台可粘贴文本、选择 TXT/Markdown，先创建任务再执行；同来源名称替换该来源，保留其他来源。文本上限 100 万字符，前端文件上限 1 MB。本地源目录继续支持 TXT/Markdown/PDF/DOCX。

`knowledge_jobs` 保存源快照、分块配置、任务状态、失败原因和生成版本。状态为 queued/building/completed/failed，失败可重试；本地文件保存字节快照，解析失败不会先删除旧索引。任务一次执行一个，运行在请求工作线程，没有另启队列 worker，客户端超时后应先刷新任务状态。

候选知识先完整生成向量并写入独立 Chroma 集合，校验片段数量，再原子替换 active manifest；旧集合保留供回退。切换或构建失败继续使用旧索引。重建本地知识入口也不再先清空集合，且保留手动来源。

已完成任务重复执行直接返回原结果。若索引已发布、SQL 完成状态尚未落库就发生中断，重试会检查当前版本的任务标识并补全完成记录，避免再次向量化。PostgreSQL 与 Chroma 仍是两种存储，不是跨库原子事务；其他管理动作已切换版本时，可重新执行任务生成版本，管理员需核对当前版本。

后台可查看版本和确认回退；回退不改历史回答保存的参考快照。当前没有自动回收旧版本，需观察存储量后确定保留策略。manifest、知识源和 Chroma 数据应一起备份。

### 5.4 质量评测

`resources/evaluations/ai_cases.json` 提供 8 项基础问题及人工核查要点。`python -m app.evaluate_ai` 默认只生成人工评审清单，不请求模型，不把未执行条目标成通过。可传 `--results 文件` 汇总已收集回答与来源；可选 `--retrieve` 调用配置的 Embedding/Rerank 服务，记录来源命中与耗时，可能产生服务费用。

来源命中率不等于回答事实正确率；急症、药量、种类适配与私人信息需人工核查。此次没有运行付费模型质量评测，也没有真实 OSS 上传测试；没有已核算的 token 成本、预算控制或高并发服务指标。

## 6. 数据与资源职责

| 存储 | 职责 | 故障与数据规则 |
| --- | --- | --- |
| PostgreSQL | 账号、帖子、宠物、关系、收藏、通知、举报审计、聊天轮次、知识源任务 | 业务唯一事实源，由 Alembic 管理 |
| Redis | 注册、改密、社区写入限流及独立 TTL 工具 | 不保存账号或聊天唯一副本；故障不妨碍已有账号登录与公开读取 |
| Chroma | 向量集合与知识版本 | 不再先清空重建；旧版可回退 |
| OSS | 社区图片、头像、AI 私人附件 | 私有前缀与权限校验，社区不能直接绑定 AI 私人附件 |

Redis 仍未接入社区服务端查询缓存、通知队列和推荐。前端新增的列表缓存是浏览器内存缓存，与 Redis 无关。写入限流依赖 Redis 时，故障返回 503，超限 429 + Retry-After，不静默回退 SQLite 或放行。

600 秒内当前每账号额度：发布 10、编辑 30、社区上传 60、评论 30、点赞及取消 120、举报 10、头像上传 10、宠物创建编辑 30、关注及取消 120、收藏及取消 120。注册另有手机号/IP 范围，改密保留原配置；重试也计额度。Lua 原子检查多范围，key 范围摘要化，使用 Redis 时间。Compose AOF everysec、256 MB、noeviction 与独立数据卷。

社区图片验证 JPEG/PNG/WebP，10 MB、2000 万像素上限，纠正方向、移除元数据、输出 WebP，详情 1600px、缩略图 480px。头像上限 5 MB、输出 480px。OSS `community/<id>/` 与 `avatars/<id>/` 私有，读取先校验可见性并返回 no-store；Bucket 不能另行匿名开放这些前缀。

未引用社区图片至少保留 24 小时，清理检查帖子和未删除宠物，下架引用仍受保护。命令 `python -m app.clean_community_media`，未配置自动定时任务。头像替换后尝试删除旧对象，失败记录待清理 ID；没有头像孤立对象自动任务。

分层规则继续生效：API 做请求、身份与响应；服务做业务规则与事务协调；仓储做数据库读写；基础设施做 SDK 适配。不在 API 执行 SQL，不在仓储反向导入服务，不在服务依赖 FastAPI。事务内共享连接，不能将一次业务拆成多次独立提交。`tests/test_architecture.py` 自动检查这些边界。

本轮具体工程变化：

- 同数据库 URL 的仓储共享进程内连接池，最大 8 个连接；仓储关闭按引用释放，避免每个仓储独开池。数据库操作耗时包含获取连接等等待。
- 请求返回 X-Request-ID，并记录路径、状态、总耗时、数据库操作次数和耗时；不记录请求体、密码、令牌、私人咨询正文。
- 后台用户搜索/分页下推 SQL；历史读取解耦；同步 SDK 路由使用同步入口，异步后台和流式任务中的数据库操作在线程池执行。
- 信息流缓存按账号令牌与完整查询路径隔离，最多 10 组、60 秒。返回列表可恢复已加载页与滚动；成功写入或切换账号清理缓存，旧请求不能重新填充失效缓存。手动刷新强制请求。其他用户修改内容最多在该 TTL 后重新获取，图片仍按服务端权限读取。
- 全局路由重建策略继续保留，未一次替换 Vue 项目为 TypeScript；新增 DTO 声明作为逐步收紧契约的起点。
- 弹窗初始焦点、Tab 范围及关闭后焦点还原；个人资料未保存离开提醒；窄屏后台已检查。
- CI 配置后端真实 PostgreSQL/Redis、前端单元/构建/浏览器和隔离真实 API 联通；本地检查脚本可统一执行。没有推送代码或声称远端 CI 已执行。
